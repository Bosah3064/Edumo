======================================================================
1. PRODUCT
======================================================================
Edumo is SaaS: a school or academy group self-registers, verifies itself, and
gets an isolated workspace with its own branding, settings, roles and data.
A standalone school = an Organization with one branch.
Hierarchy: Organization -> School/Branch -> Campus/Section (optional) -> Class/
Stream -> Learner. A group owner can add, remove and merge branches, see
consolidated reports across branches, and drill into one branch. A learner may
transfer between branches, including across countries, keeping their history.

Differentiators (build to these):
- Mobile-first, OFFLINE-FIRST marks and attendance entry for weak connectivity.
- Real Excel import/export that works (competitors' import/reports are weak).
- Correct handling of CBC and other East African grading systems.
- Multi-branch consolidation for academy groups.
- Privacy as a feature: school data is never shared or used for marketing.
- Parent reach via push, SMS and WhatsApp fallback, low-data mode.
- Teacher task tracker (what each teacher still has to mark/enter/comment).

5. SECURITY (NON-NEGOTIABLE)
======================================================================
1. Deny-by-default Firestore and Storage rules; every collection explicitly allowed.
2. Authorization via custom claims; clients can never set or change claims/roles.
3. Rules enforce tenant isolation (orgId/schoolId in path must match claims),
   role-based access, and field-level validation (types, sizes, allowed fields,
   immutable fields: orgId, createdAt, createdBy).
4. Parents read ONLY learners they are verified guardians of; students only their
   own data; teachers only assigned classes; branch staff only their branch;
   restricted data (medical, counselling, safeguarding) only by explicit permission.
5. Sensitive operations ONLY via callable Cloud Functions with Zod validation:
   create organization, add/merge branch, invite user, assign role, link guardian,
   import/export, publish results, record payment, delete/export personal data.
6. Invitation-based onboarding: expiring, single-use invite links/codes.
7. App Check enforced on Firestore, Storage and Functions.
8. Audit log for role changes, grade/mark changes, publishing results, payments,
   exports/imports, data deletion and admin logins.
9. Storage: tenant-scoped paths, file type and size limits, no public reads,
   short-lived signed URLs.
10. No secrets in client code; use Secret Manager.
11. Rate limiting on auth, invite, OTP, export and messaging functions; email or
    phone verification required; optional 2FA, enforced for admin roles.
12. Spreadsheet formula injection defence on BOTH export and import
    (neutralise cells starting with = + - @ tab or CR).
13. Prompt-injection and XSS hygiene: sanitise all user-provided rich text; strict
    Content-Security-Policy headers on Hosting.
14. Privacy by design: consent records, data export and deletion requests, soft
    delete with retention policy, data-access log visible to school admins,
    minimal collection, no cross-school data sharing, per-country legal settings.
15. EMULATOR TESTS (@firebase/rules-unit-testing) proving at least: org A cannot
    read or write org B; a parent cannot read another family's child; a teacher
    cannot access unassigned classes; a client cannot change its own role or
    claims; unauthenticated access is denied everywhere; cross-tenant export
    attempts are denied; a branch user cannot see another branch. All must pass.

6. COUNTRY PACKS (data, not code)
======================================================================
Each pack contains: curriculum templates and grade structures, grading scales,
academic calendar defaults, currency and minor units, payment providers, report
templates, government export formats (pluggable), data-protection defaults, and
language packs. Schools pick a pack at registration and can override everything.
Seed packs (all values editable and flagged VERIFY WITH OFFICIAL SOURCE):
- KENYA: CBC levels EE1, EE2, ME1, ME2, AE1, AE2, BE1, BE2 (points 8..1) with
  strand/sub-strand assessment; a NO-AGGREGATE mode (no total points across
  subjects, no mean grade, no school mean, no class ranking in KJSEA-style
  reports, enforced in the report layer); classic marks/rank mode for schools
  still using it; three-term calendar; M-Pesa Daraja; NEMIS-style export as a
  pluggable module.
- UGANDA: UNEB nine-band D1..F9 (D1 best, direction-aware sorting); continuous/
  competency assessment for the new lower secondary curriculum; MTN MoMo and
  Airtel Money via an aggregator.
- TANZANIA: NECTA Division I..IV from Best-6 (O-Level) / Best-7 (A-Level)
  aggregate with an editable boundary table; Swahili-first UI.
- RWANDA: A..E scale with editable per-subject pass threshold; Kinyarwanda,
  French, English.
- Generic packs: percentage, letter A-F, GPA, custom.
Core code must never hard-code any country's rules. Grades are stored with their
original system and country code; cross-border transfers keep history in its
original format. All grade comparison, sorting, honour-roll and pass/fail logic
is direction-aware.

======================================================================

- EXPORTS must be real .xlsx: live formulas (totals, averages, balances), styled

  print setup (landscape, fit to width, repeated header rows), protected formula
  cells, multiple sheets (Summary + Details), localised headers.
- REPORTS: class list; learner master list; monthly attendance register (grid);
  attendance summary; marks sheet per class/subject/assessment; subject analysis;
  CBC learner progress data (no aggregate/rank in CBC mode); classic mark list
  with totals, means, positions (classic mode ONLY); fee statements; arrears/
  debtors; collection summary by class/day/method; payroll and staff lists;
  leave summary; branch comparison workbook; audit log export (admin only).
- CUSTOM REPORT BUILDER: choose entity, columns, filters, grouping, sorting;
  save named templates per school; schedule weekly/monthly reports delivered as
  expiring links. One shared filter component (date range, branch, class, term,
  status) is used by every list and report so behaviour is identical everywhere.
- IMPORTS: downloadable templates per entity (learners, guardians, staff, marks,
  fees, opening balances) with header notes, data-validation dropdowns, hidden
  lookup sheet, example rows. Flow: upload -> server-side parse (size/row limits,
  MIME + magic-byte check, reject macros/.xlsm, zip-bomb protection) -> DRY RUN
  with preview and row-level errors -> confirm -> batched idempotent commit with
  progress -> downloadable errors.xlsx with failing rows highlighted and reasons
  -> duplicate detection -> rollback of the last batch.
- MARKS BY EXCEL: export a pre-filled class marks template, teacher fills it
  offline, uploads it, validated against maximum marks.
- Exports/imports run through callable functions that derive orgId, schoolId and
  role from the verified token, never from request parameters. Parents export
  only their own child's statements. Files live in tenant-scoped private Storage
  with signed URLs (15 min expiry) and auto-delete after 24h. Large exports run
  as async jobs with status documents and a notification when ready. Audit-log
  every import and export. Unit-test generated files (formulas, formats, sheet
  names, row counts) and test 50,000 rows for memory and speed.
